# 切片阶段与 main ctb-tile 的对拍状态及优化方案

日期：2026-09-03。本文核对当前源码与已有实测，不修改切片业务实现。

## 对拍结论与证据边界

已进行真实 main `build_ctb_command` 所生成参数的 ctb-tile 对拍，不只是比较当前实现的单元测试。基线为本地 main e980d49227611fcb16f840ee6381cac9d7a300d5，以及固定的 cesium-terrain-builder:local 镜像。基线容器启动不计入核心切片耗时。

样例为 data/source 的 s85e80、s5e130、n0e0 完整 TIFF；Mesh / Geodetic / average、z10→z0、tile size 65、quality 1、error threshold 0.125、4 线程、512 MiB 缓存、法线开启。每分支三轮，相同 Linux 命名卷存储；未清空系统缓存。

对拍已覆盖：瓦片坐标集合、数量、独立 quantized-mesh 解码、三角形与边界索引、法线、共同地理坐标的表面高程、边缘剖面和共享边接缝；另有 resume、layer-only、Heightmap、Mercator 的有限功能测试。没有完成 Cesium 浏览器渲染验收、全参数和所有投影场景验收。

历史切片性能（秒，三轮中位数）：

| 样例 | main | 当前历史值 | 当前/main | 瓦片数 |
|---|---:|---:|---:|---:|
| s85e80 | 1.922 | 5.665 | 2.95× | 1164 |
| s5e130 | 2.009 | 6.508 | 3.24× | 1164 |
| n0e0 | 2.071 | 6.302 | 3.04× | 1220 |

预处理优化后的端到端单轮回归，切片分别为 5.697、6.207、5.857 秒，数量相同。它不是新一轮 main/current 成对三轮基准，不能与历史中位数拼成严格的新加速比。

历史准确度问题：n0e0 有效源覆盖内的边缘采样，当前最大源参考误差约 1940.18 m，main 约 183.53 m；靠近西边界的更密剖面显示向 0 m 抬升。当前接缝最大值虽较低，但不代表高程更准确。参考是源 DEM 双线性高程，不是测量真值；上述准确度数值尚未对优化后所有切片重新统计。

当前源码仍保留 `sanitize_tile_heights` 将无效采样置零、相邻瓦片采样等路径，所以已有问题不能因预处理通过而视为关闭。也不能未经消融就把全部误差归因于补零。

## 按顺序实施的优化方案

### 1. P0：固定同一输入，补齐阶段定位基准

把同一份已验证的预处理 TIFF 及其概览只读交给两套切片器，先隔离预处理差异；再保留各自完整流水线作为产品性能比较。记录实际参数、输入/原生二进制哈希、CPU、压缩及写盘策略。

新增阶段观测：栅格读取与解压、坐标变换/重采样、相邻样本网格、原生简化与编码、gzip、文件写入/同步、元数据。统计调用次数、解码块数、缓存命中、队列水位、墙钟耗时、CPU 时间和进程树内存峰值。线程阶段累计耗时可能重叠，不可直接相加冒充总耗时。

以 n0e0 西边缘固定坐标作为最小回归，分别比较源窗口、采样网格、sanitize 前后、编码后的表面。优先使用固定版本 CTB 源码或测试构建导出中间样本，golden 不由当前算法自身生成。

### 2. P0：修正有效区边缘的采样及补零策略

涉及 `app/services/ctb/sample.py`、`raster/warp.py`、`raster/resample.py` 和原生网格编码。

- 分开记录源覆盖外、源内 NODATA 和有效像素，保留有效性掩膜到边缘策略决策处。
- 校验 overlap affine、像元中心、average 足迹裁剪、概览选择和 halo，确定误差首次出现在哪一层。
- 有效像元不得在平均或三角形拟合中被覆盖外的 0 m 拉高；比较 CTB 的掩膜处理与边界约束。若必须生成覆盖外顶点，应明确采用哪种外推/填值策略，并约束有效区边缘顶点，避免跨有效性边界形成长斜坡。
- 共享边采用同一地理坐标采样和一致量化约束，同时检验源参考误差与接缝误差。不能只恢复 sentinel，也不能只以“裂缝变小”为验收条件。

先验证边界行为再做性能缓存，否则会固化错误输出。main 自身的异常也不应复制为产品目标。

### 3. P0：补齐本项目可见功能与异常输出

- `tiler.py` 的 Mercator layer.bounds 当前写网格投影坐标，而预览使用 fromDegrees：转换为经纬度边界，并验证 projection、available、定位及实际加载。
- Heightmap 的 uint16 高程编码在低于 -1000 m 时出现回绕（双方共有）：编码前明确范围检查，越界给出可理解错误并提示使用 Mesh；不得静默截断/回绕。范围上界也应按编码量化验证。
- 根瓦片 horizon occlusion point 的非有限字段（历史双方共有）：定位空根、退化几何与极区路径，构造有限且符合消费者剔除语义的结果，不能任意用 0 替代。加入 Cesium 加载/剔除回归。
- `error_threshold`、`warp_memory` 在当前 schema 标为不生效，`creation_options` 未在当前 tiler 应用，而 main 会传给 CTB。逐项决定实现对应语义或显式拒绝非默认值；建立能力表，不能静默接受后称为参数兼容。
- 保留当前准确的 Geodetic bounds 和法线声明；比较项目最终发布结果，不只比较 CTB 是否直接输出 layer.json。

### 4. P1：减少相邻样本重复计算

`_encode_tile` 对自身采样，并在需要时由 `_neighbor_heights` 对相邻完整网格采样；同一网格可能被多个任务重复计算。

依据第 1 步计数决定采用按层、空间邻近的小批任务或有界样本网格 LRU。缓存键包含数据版本、z/x/y、profile、tile size、重采样方法及无效值策略。缓存只读结果，并用 single-flight 防止同键并发重复计算；计算时不持有全局锁。批次结束及时淘汰。验证法线/边界结果不随线程数或任务顺序变化。

### 5. P1：减少解压、转换和内存复制

当前使用每线程 GeoTiffReader，已有按线程分配缓存，不能简单再给每线程一份完整预算。先看解码块重复率，再选择每线程局部性优化或受锁保护的共享不可变解码块缓存；共享 reader 需要验证 tifffile 文件句柄和解码线程安全。

复用变换器和规则坐标网格，复用连续 Float32 缓冲，减少 sample/sanitize/原生包装间复制。只有剖析表明 Python 采样仍主导时，才把相应热点并入原生内核；网格编码已释放 GIL，不必重复重写。内存预算同时涵盖 reader、样本网格、原生工作区和待写队列。

### 6. P1：优化写出与并发

`_atomic_write` 当前逐瓦片创建临时文件、flush、fsync、chmod、replace。先独立测量其耗时占比，再评估有界写队列、目录预创建和批量任务调度。维持原子可见性；若改为阶段同步或允许重算的缓存模式，必须明确崩溃持久化语义，测试中断、resume 和残留临时文件，不能仅删除 fsync 来制造不可比的加速。

依据 gzip 占比测试压缩等级，使用解码后语义和体积评价；把默认等级改变单独列出。测试 1/2/4/8 线程，观察 CPU 配额、CPU 时间、内存与吞吐的拐点；生产多任务并发时避免每任务均抢满机器。

### 7. P2：扩展兼容性矩阵及浏览器验收

补充真实 NODATA、跨 TIFF 接缝、其他 CRS、日期线、高纬、z11 以上、tile size、quality、重采样方法、无/有法线、resume 中断恢复。对 Geodetic/Mercator 均跑本库 Cesium 预览，核验加载、定位、LOD 切换、海底边缘及遮挡剔除。

## 建议验收门槛

以下为待采用的门槛，不是现有全面保证：

1. 相同输入和受支持参数的瓦片集合、结构、索引及法线扩展合法；需要有限的元数据字段全部有限。布局差异不要求 gzip 字节相同。
2. 固定坐标比较表面，不直接对齐两套不同顶点列表。分别报告内部/海岸/源边界/共享边误差分布和最差点；源边界千米级异常消失，误差不劣于 main 的约定容差，同时接缝不退化。具体米级容差按分辨率、LOD 与 quality 制定，不能照搬预处理的 1e-3 m。
3. 多线程、缓存大小和任务顺序不改变语义；功能开关与错误行为符合能力表。
4. 每项优化先做单变量消融，至少三轮成对测量；同一 TIFF 和相同持久化/压缩语义下，建议第一阶段把切片耗时压到 main 的 1.5 倍以内，再争取接近 main。此为目标，无已验证加速倍数承诺。
5. 峰值内存、输出体积、单任务速度及多任务吞吐一同报告，不能用无界缓存换取短时成绩。

原始证据：`docs/BRANCH_EVALUATION_20260903.md`、`data/evaluation_20260903/{timings,accuracy,features_main,features_current,profile}.json`；预处理优化后运行回归：`data/preprocess_optimization_20260903/end_to_end.json`。本方案未新增性能实测，也未将旧准确度数字标作最新结果。
