# 预处理阶段对拍与优化方案

> 后续实施已完成，变更、复测数据和适用范围见 [优化实施说明](PREPROCESS_OPTIMIZATION_RESULTS.md)。下文保留优化前诊断结果。

日期：2026-09-03。对象为当前 main-zy 工作区（含既有未提交修改）与本地 main e980d49。没有修改业务实现。

## 判断

可以对拍，而且应该以 main 的 GDAL 3.12.4 输出作为兼容性基线；目前不能认定预处理语义完全等价。已有完整 TIF 测试显示当前预处理更快、更省磁盘，但没有孔洞的样例掩盖了填充差异。

对拍应比较解码后的 CRS、仿射变换、宽高、有效性掩膜、有效像素与每级 overview，不要求 TIFF 二进制相同。压缩、内部/外部 overview 与标签排列可以不同，前提是消费者读取到的地理位置、高程和有效性一致。main 是兼容性参考，不是地形测量真值。

## 实测差距

完整源数据预处理耗时沿用前一轮相同存储、4 CPU 配额、三次测量中位数，单位秒；未把切片耗时归到预处理。

| 样例 | main | 当前 | 当前耗时减少 |
|---|---:|---:|---:|
| s85e80 | 3.690 | 2.805 | 24.0% |
| s5e130 | 3.739 | 3.547 | 5.2% |
| n0e0 | 5.573 | 3.208 | 42.4% |

5.2%的差距小于部分轮次波动，不宜宣称稳定优势。当前最终 DEM 加概览占用约2.69/16.90/15.59MB，main约194.20/97.11/194.23MB。完整样例均无实际NODATA孔洞，以上速度不能外推到大量缺失值场景。内存峰值尚未实测。

本轮新增阶段隔离探针：从 s5e130.tif 的像素偏移(1800,1800)裁剪宽515×高513的真实数据并转成Float32；注入跨256块边界的12×12孔洞及30×30孔洞。另用31×31、仅两个斜向有效点的最小用例检验邻域和NaN行为。该稀疏用例是语义诊断，不用于评价稀疏点地形重建质量。

| 项目 | 结果 | 定位 |
|---|---|---|
| 同CRS处理 | 前轮两个完整TIF多出一列或一行 | 同CRS也重新计算像元大小、ceil尺寸 |
| EPSG:4326→3857默认网格 | main宽513×高515，当前宽516×高514 | main像元约93.0859m正方形；当前约92.5865×93.2253m |
| 同一目标网格的bilinear | 最大差3.8147e-6m，MAE4.5474e-11m | 本例采样内核高度一致，先修网格规划 |
| 真实DEM孔洞，sentinel或NaN | 双方均剩100个未填像素，但944个共同填充像素MAE16.4611m、最大191.3684m | 填得出不等于填值等价 |
| 斜向有效点，sentinel | main剩386无效，当前剩881；495像素掩膜不同 | 中心main=150m，当前仍是-32768 |
| 斜向有效点，NaN | main剩386无效，当前剩959；当前没有新增有效像素 | 当前还存在NaN计算污染风险 |
| 2倍overview | main宽258×高257，当前宽257×高256 | 当前使用整数向下取整 |
| 4/8/16倍overview | main129²/65²/33²，当前128²/64²/32² | 大小、边缘覆盖语义不同 |

当前 fillnodata.py 只沿同一行、同一列找最近有效点；GDAL规定的是四方向锥形搜索和反距离加权，不能把两者视为同一算法。[GDAL算法说明](https://gdal.org/en/stable/api/gdal_alg.html)

当前重投影使用四角局部最小像元尺度、分别计算x/y尺寸；GDAL有自己的输出网格建议算法，默认重投影网格并不因此等价。[GDAL重投影说明](https://gdal.org/en/stable/programs/gdal_raster_reproject.html)

## 优化顺序

### P0：修正输出网格，同时避免无意义重采样

涉及：`app/services/raster/reproject.py`、`crsutil.py`。

- 对同CRS、北向、无旋转/剪切、没有显式改变分辨率/范围的输入，直接保留原始affine、width、height。不要通过“大坐标相减得到像元尺寸，再ceil回像素数”重建原网格。
- 仍需压缩或分块时采用不插值的逐块转存；只有文件布局、NODATA语义和概览均满足要求时才考虑跳过物化。不能直接在源文件上填洞或增加overview，也不要可写硬链接回源文件。
- 不同CRS引入显式目标网格对象：CRS、affine、width、height。网格规划与重采样分离。
- 先由固定版本GDAL输出目标网格建立golden，再实现兼容网格规划。不能只增大ceil epsilon，也不能只强制正方形像元便宣称兼容。
- 沿用当前bilinear内核，先在固定网格验证更多投影、NODATA边界及旋转输入，再决定是否需要改内核。

预期收益：消除同CRS尺寸漂移和额外重采样；无重投影需求的数据可少一次插值计算。没有实测优化后的加速倍数。

### P0：重做填充邻域语义，修正NaN传播

涉及：`app/services/raster/fillnodata.py`，后续原生内核可放入现有C++扩展。

- 对齐GDAL 3.12.4的锥形邻域搜索、距离限制、权重、搜索顺序、掩膜与无法填充规则；不能仅增加四条对角线近似替代。
- 使用原始有效性掩膜决定供体，防止分块/线程顺序改变传播结果。
- 累加时仅索引有效供体；不能用`NaN * 0`表示“忽略供体”。当前`weighted += val * weight`可能把非有限值带入累加结果。
- 对整数输入校验舍入、饱和与NODATA恢复；当前`np.rint`的半值取整语义需要单独golden验证，尚未证明与GDAL完全一致。
- 先通过Float32、整数、sentinel、NaN、边界洞、全无效、孤立供体和超搜索半径用例；再将已校准算法移入C++/Cython。
- 若短期要求严格兼容且允许GDAL依赖，可提供显式GDAL兼容后端作为过渡；若保持去GDAL目标，则固定版本golden只在测试环境使用。不要静默在生产环境回退。

### P0：概览尺寸和采样范围整体对齐

涉及：`app/services/raster/overviews.py`、`geotiff.py`、`resample.py`。

- 按golden确定各级宽高；本次奇数尺寸应采用向上取整覆盖末行/末列。
- 仅把`//`改为ceil不够：overview应按`base_width / overview_width`、`base_height / overview_height`的实际比例建立像元足迹与仿射变换，读写双方一致。
- 当前writer写`src.affine.scaled(level)`，reader却按整幅范围/overview实际尺寸重建affine；应消除两套尺度定义。
- 对最右/最下残块使用真实相交面积与有效像元权重；不能丢掉尾部像素，也不能把TIFF块padding当作有效0m。
- 内部overview与外部`.ovr`均应被当前reader和GDAL读出同样的尺寸、覆盖范围和掩膜。保留压缩优势，不必强制采用main的大文件布局。

### P1：正确性通过后减少数据扫描、复制和峰值内存

涉及：`app/services/preprocessor.py`、`raster/fillnodata.py`、`raster/geotiff.py`、`raster/parallel.py`。

- 在读取/转存或重投影时累计有效性统计，将“是否仍有无效值”作为阶段结果传递。确认没有孔洞后省去填充重写；仅凭没有NODATA标签不能推断没有NaN/Inf或mask。
- 概览读取阶段可以复用受预算限制的块缓存；保留当前最终重命名流程和压缩，不恢复main的最终全量复制。
- 修正内存预算：目前`H*W*8 <= cache_bytes`只估计一个Float64平面，但填洞还生成四组距离/值数组、掩膜、权重和副本。36M像素的8个Float64邻域平面本身就约2.3GB，512MiB参数并不是进程峰值上限。这是源码估算，不是本次RSS测量。
- 为reader缓存、阶段工作数组、并发任务和写队列设统一预算，默认流式块+halo，按实际工作集选择全图路径。限制队列深度，不要让多个阶段各自“用满512MiB”。
- 预处理worker数可配置，并考虑CPU配额/亲和性、可用内存；不要只取`os.cpu_count()`。对1/2/4/8线程测吞吐与RSS，选择拐点，避免过度并发。
- 进一步融合阶段前，确保不会改变填洞供体与overview构建顺序；先做单阶段优化再验证融合。

## 建议验收门槛（待业务采用，非现状保证）

1. 同CRS保留模式的宽高和affine保持原值，有效像素不变；跨CRS兼容模式输出网格与固定版本golden一致，仿射容差换算到源像素后明确控制。
2. 无效掩膜一致、overview级数/尺寸一致、边缘像素不丢失。
3. 同网格Float32样例先以最大绝对差≤1e-3m为工程门槛；整数用例优先逐值一致。若不达标，逐阶段解释，不用全图平均值掩盖填充区最大误差。
4. 对拍记录reproject/fill/overview/最终转存各自耗时、峰值RSS、临时字节、重复轮次、CPU限制和输出哈希；性能测量必须在语义门槛通过后比较。
5. 回归样例覆盖偶数/奇数尺寸、块边缘、负海深、NaN/sentinel、实际孔洞、同/异CRS和overview有效性。填充实现同时验证全图/分块路径、不同缓存预算及worker数的输出一致性。
6. 预处理对拍通过后再重跑切片。此前海底边缘1940m误差发生在网格采样/编码链路；`n0e0`主分辨率预处理已逐像素相同，不能承诺预处理优化会自动解决该切片问题。

## 执行建议

按“阶段golden和断言 → 同CRS网格 → 填洞语义/NaN → overview范围 → 跨CRS规划 → 内存与跳步 → native并行”顺序拆成独立变更。前四项完成前，不建议将当前实现标记为main预处理的等价替代。

证据：`benchmarks/probe_preprocess_parity.py`；`data/evaluation_20260903/preprocess_probe_main.json`和`preprocess_probe_current.json`。测试原始TIF/NPZ位于命名卷`/data/preprocess_probe_20260903`。完整源数据耗时参见`docs/BRANCH_EVALUATION_20260903.md`与`data/evaluation_20260903/timings.json`。
