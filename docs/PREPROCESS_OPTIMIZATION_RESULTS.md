# 地形预处理优化实施说明

日期：2026-09-03。在 `main-zy` 当前工作区实施，保留原有未提交修改；对拍基线为本地 main `e980d49227611fcb16f840ee6381cac9d7a300d5`。本次改动尚未提交或部署。

## 按方案顺序完成的变更

| 顺序 | 实现 | 原因与效果 |
|---|---|---|
| 1：阶段基准 | `tests/fixtures/preprocess_gdal_3124.json`、`test_preprocess_parity.py` | 使用独立 GDAL 3.12.4 生成填洞、概览和目标网格 golden，避免用当前实现生成自己的期望值。 |
| 2：同 CRS 网格 | `raster/reproject.py` | 北向、无旋转/剪切且 CRS 不变时直接保留原始 affine、宽高；分块转存不插值，消除多行/多列问题。仍写独立输出，不修改源 TIFF。 |
| 3：填洞及 NaN | `raster/fillnodata.py`、`ctb/native/fill_nodata.hpp`、`_ctb_core.pyx` | 改为原始有效供体的四象限最近点搜索和反距离权重，半径默认 10 像素。仅累加有效供体；不能填充的点保留无效语义。整数写出按半值远离零舍入并饱和。 |
| 4：概览 | `raster/overviews.py`、`geotiff.py`、`byte_progress.py` | 向上取整尺寸，按真实宽高比例计算像元足迹；处理末行/末列及 GDAL 无掩膜 2×2 特例。逐级构建、flush 后读取前级；修正整图缓存误代概览的问题。进度字节预算同步使用新尺寸。 |
| 5：跨 CRS 网格 | `raster/crsutil.py` | 对有限、连续的仿射投影路径采样周界，以对角线估计正方形像元并规划输出宽高。固定网格仍使用现有 bilinear 内核。加入 UTM→4326、3857→4326、旋转 4326→3857 的独立网格基准。 |
| 6：扫描与内存 | `preprocessor.py`、`reproject.py`、`fillnodata.py` | 转存/重投影时统计无效像素；确定没有孔洞后跳过填洞重写。填洞使用块加 halo，按预算细分计算块。能装入读取器半预算的源图可整图缓存，否则流式读取；避免条带 TIFF 重复遍历。 |
| 7：原生计算与并发约束 | `mesh_encode.py`、`parallel.py`、`native_check.py`、`setup.py` | 填洞进入 C++/Cython 并释放 GIL；重投影/概览并发受 CPU 配额、亲和性、环境上限和工作集估算约束，队列有界。概览每级结束关闭读取器并释放缓存。原生自检要求新符号，防止旧二进制被误用。 |

填洞文件阶段保留串行流式调度，原生内核负责计算；本次未宣称已完成所有机器上的 1/2/4/8 线程吞吐调优。新增 `OTH_RASTER_WORKERS` 可设置预处理默认线程上限，必须为正整数；未配置时参考 CPU 配额和亲和性。它与切片参数 `thread_count` 是不同控制项。

同时修正重复使用工作目录时的旧 `.ovr` 残留：新输出没有概览时删除旧目标概览，避免读到上一次数据。GDAL 填洞改编代码的 MIT 许可已记录于 `THIRD_PARTY_NOTICES.md`。

## 正确性验证

完整测试集 **138 passed**，另有 2 条第三方弃用提示。测试在隔离开发镜像中从当前源码构建原生扩展后执行；后续纯 Python 调整复用同一扩展。

以 `data/source` 的 s85e80、s5e130、n0e0 三份完整 TIFF 为样例，使用独立 GDAL 解码比较 main 与优化后输出：

- 三份主分辨率 DEM 的宽高、CRS、affine、有效性掩膜和有效像素全部一致，最大高程差为 0。
- 四级概览的数量、尺寸及无效掩膜一致。s5e130 和 n0e0 全部概览逐值一致；s85e80 最大差 `0.000244140625 m`，低于 `1e-3 m` 工程门槛。
- 真实 DEM 裁剪后注入 sentinel/NaN 孔洞，944 个填充值与 main 一致；稀疏斜向供体样例的掩膜、573 个新增有效像素及中心 150 m 一致。修复前真实孔洞最大差约 191.37 m，稀疏样例存在漏填及 NaN 污染。
- 真实裁剪的 4326→3857 网格恢复为宽 513、高 515；bilinear 最大高程差约 `3.8147e-6 m`。额外三个投影/旋转样例的尺寸一致，affine 绝对容差 `1e-7` 通过。
- 回归覆盖块边界、不同缓存预算、同 CRS 精确保留、奇数概览、整数半值舍入、无孔洞跳步、源文件字节不变、进度单调及旧概览清理。

main 是兼容性基准，不是地形测量真值。跨日期变更线、投影奇点、RPC/GCP、独立 TIFF mask/alpha 等尚未建立完整兼容性矩阵；仍保留原有 Web Mercator 高纬裁剪路径，不能宣称任意 GDAL 输入完全等价。

## 最终性能复测

同一 Docker 环境、4 CPU 配额、512 MiB 参数、256 块、EPSG:4326、填洞及概览开启。每个样例/轮次单独进程，计时不含容器启动；每组 3 次取中位数。main 使用本地 main 的真实 GDAL 阶段；当前使用工作区 Python 和新编译原生扩展。没有清理 OS 磁盘缓存，结果是本机常规缓存条件下的预处理表现。

| 样例 | main 秒 | 优化后秒 | main / 优化后 | main 峰值 RSS MiB | 优化后峰值 RSS MiB |
|---|---:|---:|---:|---:|---:|
| s85e80 | 3.688 | 1.000 | 3.69× | 554.75 | 246.43 |
| s5e130 | 4.131 | 1.365 | 3.03× | 344.19 | 191.95 |
| n0e0 | 6.327 | 2.002 | 3.16× | 554.80 | 305.85 |

RSS 为每轮 Python 主进程/子进程中最大的单进程高水位，再取三轮中位数，并非进程树同时驻留内存之和。512 MiB 是缓存及任务调度预算，不是硬性进程 RSS 限制：Python、压缩器、线程、最小 TIFF 块/halo 及源读取临时分配另有开销。

| 样例 | main 最终 DEM+概览 MB | 优化后 MB | main 预处理目录总 MB | 优化后总 MB |
|---|---:|---:|---:|---:|
| s85e80 | 194.20 | 1.70 | 388.94 | 1.70 |
| s5e130 | 97.11 | 15.92 | 202.30 | 15.92 |
| n0e0 | 194.23 | 28.90 | 393.69 | 28.90 |

MB 按十进制。压缩布局与 main 不同，但上述解码语义已经验证。优化前当前分支的历史中位数为 2.805/3.547/3.208 秒，可作为方向参考；它们属于前轮测量，不能与本轮混用计算严格加速比。中间试验的强制分块读取较慢，因此最终保留了受预算限制的整图读取路径。

三份完整输入没有实际孔洞，跳过填洞是其主要收益之一；大量缺失值数据只有正确性用例，本次速度不可直接外推。缓存释放前的中间轮次也保留在 Docker 卷中，报告采用最终版本 `current_7/8/9`，main 为 `main_1/2/3`。

## 下游与使用说明

三份完整数据已重跑至 geodetic quantized-mesh 切片，z10→z0、4 线程：分别生成 1164、1164、1220 个 terrain 文件，均生成 layer.json。切片阶段单次耗时约 5.70/6.21/5.86 秒，仅作端到端运行回归。该轮位于最后一次缓存生命周期收紧之前；随后完整测试及整图对拍仍通过，计算语义未改变。

本次没有修复此前报告的网格边缘采样、根瓦片 horizon 非有限值或 heightmap 海深编码问题，也没有把预处理加速等同于切片核心加速。

新实现需要重新构建 Cython/C++ 扩展，生产使用应按仓库现有镜像构建流程重建相关镜像；单独替换 Python 文件不足以启用。已在隔离容器编译并验证，未重启现有服务。

证据位于 `data/preprocess_optimization_20260903/`：`timings.json`（逐轮及分阶段耗时）、`whole_raster_parity.json`、`stage_probe_current.json`、`stage_probe_main.json`、`end_to_end.json`、`native_sha256.txt`。此数据目录被仓库忽略；如需跨机器复核应单独保留。

可复现脚本：`benchmarks/generate_preprocess_golden.py`、`run_preprocess_checks.py`、`benchmark_preprocess_optimized.py`、`validate_preprocess_optimized.py`。它们沿用本次 `/code`、`/source`、`/baseline`、`/data`、`/export` 容器挂载约定；计时脚本的输出目录要求不存在，以免复用旧产物。
